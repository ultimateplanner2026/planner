Why. Two different things decide what sits on a day, and only one of them listens to the date.

a plain task  → shown because date says so  → clear the date, it goes ✓
a repeating item → shown because the repeat rule says so  → clear the date, the rule still says so ✗

The rule that answers “does this belong on Monday?” starts by checking that the item repeats, and never looks at whether it has a date at all. Worse, when no start date is set it treats today as the start — so an item you have just un-dated matches from today onwards, forever.

Measured across every kind of repeat, with the date cleared:

repeatafter clearing the date
daily · every 2 days · weekly · weekly on set days · monthly · monthly on a day · yearly · specific dates · with a start date setall 11 stay on the calendar
no repeat at all (a plain task)leaves correctly

So it is not one routine misbehaving — it is every repeating item, in every view. A plain task is the only thing that clears properly, which is why it looks random: it depends on whether the item you happened to clear repeats.

What the fix does. An item with no date is not on the calendar, whatever its repeat rule says. It stays in the tree with its rule intact — give it a date again and the routine resumes exactly as before. Nothing is deleted and no repeat setting is touched.
